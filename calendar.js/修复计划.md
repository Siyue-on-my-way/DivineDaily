### 修复 4: 优化闰月处理逻辑
**位置**: `src/index.js:533-542`  
**优先级**: 🟡 中  
**预计时间**: 15分钟  
**影响**: 提高代码效率和可读性

**问题代码**:
```javascript
for (i = 1; i < m; i++) {
  leap = this.leapMonth(y);  // ❌ 每次循环都重新计算
  if (!isAdd) {
    if (leap <= i && leap > 0) {
      offset += this.leapDays(y);
      isAdd = true;
    }
  }
  offset += this.monthDays(y, i);
}
```

**修复方案**:
```javascript
// 在循环外计算一次，提高效率
const leap = this.leapMonth(y);
for (i = 1; i < m; i++) {
  if (!isAdd && leap > 0 && leap <= i) {
    offset += this.leapDays(y);
    isAdd = true;
  }
  offset += this.monthDays(y, i);
}
```

**验证方法**:
- 测试各种闰月年份的转换
- 确保结果与修复前一致
- 验证性能提升（虽然影响很小）

## 🟢 低优先级修复（代码质量改进）

### 修复 5: 改进参数验证
**位置**: `src/index.js:329-340` (solar2lunar) 和 `src/index.js:501-524` (lunar2solar)  
**优先级**: 🟢 低  
**预计时间**: 20分钟  
**影响**: 提高代码健壮性，防止无效输入导致的问题

**问题代码**:
```javascript
solar2lunar: function (yPara, mPara, dPara) {
  let y = parseInt(yPara);
  let m = parseInt(mPara);
  let d = parseInt(dPara);
  // 缺少 NaN 检查
  if (y < 1900 || y > 3000) {
    return -1;
  }
  // ...
}
```

**修复方案**:
```javascript
solar2lunar: function (yPara, mPara, dPara) {
  let y = parseInt(yPara);
  let m = parseInt(mPara);
  let d = parseInt(dPara);
  
  // 添加 NaN 检查
  if (isNaN(y) || isNaN(m) || isNaN(d)) {
    return -1;
  }
  
  if (y < 1900 || y > 3000) {
    return -1;
  }
  // ...
}
```

**同样修复 `lunar2solar` 函数**

**验证方法**:
- 测试无效输入：null, undefined, NaN, 非数字字符串
- 确保都返回 -1 或适当的错误

### 修复 6: 统一时区处理方式
**位置**: `src/index.js:347` (solar2lunar) 和 `src/index.js:548` (lunar2solar)  
**优先级**: 🟢 低  
**预计时间**: 30分钟  
**影响**: 提高跨时区应用的一致性

**问题描述**:
- `solar2lunar` 使用本地时区：`new Date(y, parseInt(m) - 1, d)`
- `lunar2solar` 使用 UTC：`Date.UTC(1900, 1, 30, 0, 0, 0)`

**修复方案**:
统一使用 UTC，或添加文档说明时区处理方式。

**选项 A - 统一使用 UTC**:
```javascript
// solar2lunar 中
objDate = new Date(Date.UTC(y, parseInt(m) - 1, d));
```

**选项 B - 保持现状但添加文档**:
在函数注释中明确说明时区处理方式。

**验证方法**:
- 在不同时区环境下测试
- 确保结果一致性
